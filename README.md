## :dart: O guia para alavancar a sua carreira

> Foundation é um dos frameworks CSS responsivos mais antigos ainda mantidos: a ZURB o lançou em 2011, antes do Bootstrap adotar "mobile-first", e ele se tornou conhecido por não empurrar um visual padrão — você escreve suas próprias classes e usa mixins Sass para "puxar" o grid, os componentes e os breakpoints, o que dá mais controle (e mais responsabilidade) do que frameworks utilitários prontos. Hoje o Foundation tem atividade bem menor que Bootstrap e Tailwind — a versão mais recente, a 6.9, saiu em setembro de 2024 — mas segue mantido, é forte em acessibilidade e continua sendo referência em e-mail responsivo com o Foundation for Emails. Este guia reúne a documentação oficial, o pouco de curso e comunidade dedicados que existem para o tema, ferramentas do ecossistema ZURB e as comunidades gerais de front-end que ajudam quem estiver com Foundation em mãos. Todo link foi verificado. Use-o como apoio para os seus estudos, no seu ritmo.

## 🗺️ Roadmap

- [roadmap.sh — Frontend Roadmap](https://roadmap.sh/frontend) — O caminho completo de front-end em que um framework CSS como o Foundation se encaixa, ao lado de HTML, CSS e JavaScript.
- [Milestones do foundation-sites no GitHub](https://github.com/foundation/foundation-sites/milestones) — O que a equipe está preparando para as próximas versões, direto do repositório oficial.
- [Releases do foundation-sites](https://github.com/foundation/foundation-sites/releases) — Histórico de versões; a mais recente é a 6.9, lançada em setembro de 2024.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **HTML e CSS básicos** — o Foundation é uma camada sobre CSS puro e Sass; domine seletores, box model e Flexbox antes de começar.
2. **Instalação** — via CDN (rápido, sem build) ou `npm install foundation-sites` (compilando com Sass, para customizar de verdade).
3. **XY Grid** — o grid moderno, baseado em Flexbox: `grid-x`, `grid-y`, `cell`, `small-6`, `medium-4 large-3`. Substitui o antigo grid de float (`row`/`columns`), que ainda existe por compatibilidade.
4. **Componentes prontos** — Off-canvas, Reveal (modal), Orbit (carrossel), Accordion, Tabs, Dropdown, Sticky e Magellan (navegação por âncoras).
5. **Formulários e tipografia** — classes de formulário, grid de formulário e a tipografia base do framework.
6. **Motion UI** — biblioteca de animações Sass da própria ZURB, usada para transições em Off-canvas, Reveal e Orbit.
7. **Customização com Sass** — variáveis (`$global-width`, `$grid-margin-gutters`), mixins e funções para recompilar o Foundation com sua própria identidade visual, em vez de sobrescrever CSS por cima.
8. **Foundation for Emails** — se o objetivo for e-mail marketing/transacional, o Foundation tem um subframework próprio com grid de tabelas e a linguagem de template Inky.

**Por onde começar:**

1. **Leia a introdução oficial** em [Foundation for Sites](https://get.foundation/sites.html) — o que o framework resolve e como ele se diferencia de outros.
2. **Siga a instalação oficial** em [Installation](https://get.foundation/sites/docs/installation.html) — via CDN, npm ou os projetos-modelo prontos.
3. **Explore um projeto pronto** em [Starter Projects](https://get.foundation/sites/docs/starter-projects.html) e mexa nele localmente para entender a estrutura de pastas.
4. **Aprenda o grid na prática** com [XY Grid](https://get.foundation/sites/docs/xy-grid.html), testando `grid-x`/`cell` no navegador.
5. **Veja tudo junto** na [Kitchen Sink](https://get.foundation/sites/docs/kitchen-sink.html) — uma página só com todos os componentes, ótima para copiar trechos de HTML.
6. **Remonte um bloco pronto** dos [Building Blocks](https://get.foundation/develop/building-blocks.html), catálogo oficial de trechos de UI já estilizados com Foundation.
7. **Pratique em vídeo** com os canais generalistas de CSS/front-end listados na seção de YouTube abaixo — não há canal dedicado ao Foundation, então use-os para reforçar Sass e Flexbox.
8. **Publique no GitHub** — seu primeiro item de portfólio com Foundation de verdade, linkado no currículo.

Sua primeira página em 30 segundos (via CDN, com os hashes de integridade da versão 6.9.0 confirmados no jsDelivr):

```html
<!-- index.html -->
<!doctype html>
<html lang="pt-br">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <link
      href="https://cdn.jsdelivr.net/npm/foundation-sites@6.9.0/dist/css/foundation.min.css"
      rel="stylesheet"
      integrity="sha384-SwEFMF9is9IXVlZTFMxuzEsxVflSVaYizmWHnNx4aO+UglwnQAbMoytZUlRnClL1"
      crossorigin="anonymous"
    />
  </head>
  <body>
    <div class="grid-container">
      <div class="grid-x grid-padding-x align-middle" style="min-height: 40vh;">
        <div class="cell small-12 medium-6">
          <h1>Olá, Guia Dev Brasil!</h1>
          <a href="#" class="button">Comece aqui</a>
        </div>
      </div>
    </div>

    <!-- Foundation JS depende de jQuery -->
    <script
      src="https://cdn.jsdelivr.net/npm/jquery@3.7.1/dist/jquery.min.js"
      integrity="sha384-1H217gwSVyLSIfaLxHbE7dRb3v4mYCKbpQvzx0cegeju1MVsGrX5xXxAvs/HgeFs"
      crossorigin="anonymous"
    ></script>
    <script
      src="https://cdn.jsdelivr.net/npm/foundation-sites@6.9.0/dist/js/foundation.min.js"
      integrity="sha384-xdCzqZ2pO1GCqOAK3v4H+ymi9QkQk7SeW/bicPuWPQEJn1JfT2hJk8PFr8FVnldW"
      crossorigin="anonymous"
    ></script>
    <script>
      $(document).foundation();
    </script>
  </body>
</html>
```

Abra o `index.html` no navegador — o `grid-x`/`cell` já organiza o layout, e o `$(document).foundation();` ativa os componentes JS (Off-canvas, Reveal, Orbit etc.) que você adicionar depois.

## 🤖 IA na prática

Foundation é um caso à parte para IA generativa: como o framework tem muito menos código público e tutoriais do que Bootstrap ou Tailwind, os modelos "sabem" bem menos sobre ele. Na prática, isso significa dois riscos recorrentes: a IA **confundir sintaxe do Foundation 5 com a do Foundation 6** (o grid antigo usava `row`/`columns`/`small-6`; o XY Grid atual usa `grid-x`/`grid-y`/`cell`), e a IA **"resvalar" para Bootstrap ou Tailwind sem avisar**, porque viu muito mais desses dois em treinamento e você pediu algo genérico como "grid responsivo".

**Para aprender**
- Peça para **explicar um componente com um exemplo executável**: a diferença entre o XY Grid (`cell small-6 medium-4`) e o grid float legado (`columns small-6`), ou como o Off-canvas se conecta ao `data-off-canvas` e ao `$(document).foundation();`. Cole o exemplo em um [StackBlitz](https://stackblitz.com/) ou [JSFiddle](https://jsfiddle.net/) para ver rodando.
- Cole um layout quebrado e peça: *"essas classes são do XY Grid ou do grid float do Foundation 6?"* — depois confirme na documentação oficial de [XY Grid](https://get.foundation/sites/docs/xy-grid.html) ou [Grid](https://get.foundation/sites/docs/grid.html).
- Peça **exercícios com gabarito** sobre o tópico que está estudando (grid, Off-canvas, formulários) e resolva antes de olhar a resposta.
- Sempre que a IA sugerir uma classe ou atributo de dados (`data-toggle`, `data-off-canvas`, `data-tabs`), confirme na página do componente correspondente na [documentação oficial](https://get.foundation/sites/docs/) — Foundation muda nomes de atributo com mais frequência do que outros frameworks entre versões maiores.

**Para trabalhar**
- Use [GitHub Copilot](https://docs.github.com/pt/copilot), [Cursor](https://cursor.com/), [Claude Code](https://code.claude.com/docs/en/overview) ou [Gemini CLI](https://github.com/google-gemini/gemini-cli) para gerar a marcação HTML de componentes do Foundation, mas **sempre diga explicitamente "usando Foundation 6, XY Grid"** no prompt — sem isso, é comum a IA responder em Bootstrap ou Tailwind por serem muito mais representados nos dados de treinamento.
- Ferramentas de **design para código** como [v0 (Vercel)](https://v0.app/), [Builder.io](https://www.builder.io/) e [21st.dev](https://21st.dev/) geram interfaces a partir de um prompt — o resultado quase sempre vem em Tailwind ou React puro; adaptar para classes do Foundation exige revisão manual, não apenas um "converta para Foundation" no prompt.
- Depois de **cada** sugestão aceita, confira no navegador em telas pequenas e grandes, e confirme que o `$(document).foundation();` foi chamado — sem essa linha, os plugins JS (Off-canvas, Reveal, Orbit, Accordion) simplesmente não funcionam, e a IA raramente lembra de incluí-la.
- Para e-mail responsivo, use a IA para **explicar a sintaxe do Inky** (`<container>`, `<row>`, `<columns>`) em vez de gerar o HTML de tabela final — o Inky compila para HTML de e-mail compatível, e um HTML "genérico" sugerido pela IA costuma quebrar em clientes como o Outlook.

**Limites e boas práticas**
- A IA **mistura classes de versões diferentes** do Foundation com frequência, e é mais propensa a isso aqui do que em frameworks mais populares. Confirme sempre na [documentação oficial](https://get.foundation/sites/docs/), que indica a versão de cada exemplo.
- Ela tende a "inventar" nomes de classe plausíveis (por analogia com Bootstrap) que não existem no Foundation — sempre teste no navegador antes de confiar.
- Peça para **explicar o "porquê"** de cada classe usada — entender o XY Grid e os mixins Sass evita gambiarras de CSS customizado por cima do framework.
- Não cole design proprietário ou tokens de marca de clientes em ferramentas sem a política da sua empresa.
- Entenda o que você aceita: em entrevista e em produção, o HTML/CSS é seu — e quem mantém o projeto depois é você.

**Ferramentas de IA úteis no dia a dia com Foundation:**

## 💼 Carreira e vagas

Foundation aparece hoje em bem menos vagas de front-end no Brasil do que Bootstrap ou Tailwind — a maior parte da demanda que resta está em manutenção de sistemas legados construídos com o framework, não em projetos novos. O que vale a pena levar de Foundation para uma entrevista é o domínio de CSS/Sass responsivo e acessibilidade, que transfere direto para qualquer outro framework.
